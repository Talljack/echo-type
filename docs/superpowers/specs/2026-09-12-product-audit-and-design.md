# EchoType：全项目功能盘点与下一阶段产品设计

日期：2026-09-12。状态：设计提案，未实施。基线：本地 main / a74a8b2（v1.4.1）。

## 1. 结论与范围

定位：把用户自己的英语材料，变成每天可以完成、能够复习、可以检验实际表达能力的学习课程。

当前不是缺少模块，而是工具到课程、课程到能力、学习到跨端持久化这三段连接需要加强。不要再增加一组同级导航。

本次基于路由、关键业务实现、数据模型、导入、同步备份、原生宿主和已有设计文档进行静态盘点；不是逐行安全审计，也没有验证生产数据库策略、真实用户行为、所有供应商或真实设备。下文“拟新增”不能当成已实现功能。

## 3. 必须先处理的数据风险

证据位置：`src/lib/sync/engine.ts`、`src/lib/sync/mapper.ts`、`src/components/settings/data-backup.tsx`。

1. SyncableTable 当前只有 contents、records、sessions、favorites、favoriteFolders、journals。书籍/集合元数据、发音证据、薄弱项和媒体不在此通用同步清单中。课程索引可以派生，但派生所需源数据也必须齐全。
2. fullSync / incrementalSync 捕获各表错误后仍设置全局 lastSyncedAt。风险：失败窗口的数据随后被增量条件跳过，需要用失败重试测试确认影响并修复。
3. 会话增量筛选和映射使用 startTime；一个早已开始的会话后来完成，可能无法作为更新被上传。应使用独立 updatedAt 或追加事件。
4. pullTable 当前查询未显示分页循环。需验证超过服务端单次返回上限后的全量恢复。
5. contents 的映射未包含本地 deletedAt。Journal 已有专门删除处理，不能据此认为所有实体都实现一致删除同步。
6. 所谓完整备份的导出清单没有 mediaBlobs。恢复 JSON 不代表恢复了用户导入的音视频。

设计：账户隔离的 outbox；每次变更带 mutationId、entityId、revision、updatedAt、deletedAt；幂等重试；逐表/分区确认游标；分页拉取；服务端版本冲突检测。完成记录优先追加而非覆盖。并发文本编辑保留冲突副本，不能只用设备时间决定丢弃哪份。

媒体使用独立 Asset 和对象存储上传任务，文本同步不必等待大文件，但 UI 必须分别显示“文字已同步 / 音频仅本机 / 上传失败”。缓存可重建，用户原始文件不可视作缓存删除。

验收：双设备同时编辑、断网恢复、请求中断、重复提交、长会话后完成、分页边界、跨端删除恢复、切换账户均有测试；恢复后文本和媒体逐项校验，不得静默丢失。

## 4. 产品结构：保持五个主要入口

| 入口 | 主任务 | 子区域 |
| --- | --- | --- |
| 今日 | 今天下一步做什么 | 时间预算、今日队列、继续学习、结束小结 |
| 我的课程 | 把资料学懂并学会用 | 课程目录、课时目标、练习、结果、调整课程 |
| 学习材料 | 管理原始资料 | 所有资料、书籍、音视频、词书、导入任务、回收站 |
| 复习中心 | 找回遗忘与薄弱能力 | 统一复习队列、收藏回忆、错题、发音薄弱项 |
| 我的笔记 | 积累可再次使用的表达 | 词汇、短语、摘录、对话笔记、写作作品 |

AI 对话、发音训练继续作为专项入口；设置保持低频入口。Listen/Read/Write 等旧 URL 保持兼容，通过课程和专项进入。词书是材料类型；短语是笔记内容类型，不再重复建立一级产品。

新用户无需先配置模型：选择用途、每天可用时间，导入材料或开始一节示例课。评估可跳过，首次体验结束再邀请登录同步。示例不能依赖用户尚未配置的外部服务。

## 5. 一节真正的课程

示例：用户导入一段工作晨会材料。目标不是“完成四次点击”，而是“能够用 60 秒说明昨天完成的工作、今天计划和阻塞”。

流程：材料准备 → 理解 → 必要的语言训练 → 自主输出 → 反馈修订 → 后续复习。

- 听：无字幕听一遍，回答主旨；需要时显示对应句的译文，再听关键段。
- 读：选出阻塞原因并标记原文依据；长句拆解按需打开。
- 练：只对难词、搭配、易混音安排听写/打字/跟读，不要求整篇机械重复。
- 说：用自己的项目经历复述；反馈指出是否说明三个必要信息，再允许重说。
- 写：写一段自己的工作更新；保留初稿、建议与修改稿。
- 复习：将实际犯错或主动收藏的表达排入回忆任务，后续换语境使用。

不是每课必须全部包含。音频材料优先听力，书籍优先阅读与摘要，词书优先回忆与用法。默认短课，可拆为多个学习时段；20 词 × 4 模式不再自动成为所有词课的唯一完成定义。

完成与掌握分离：`completed` 表示有效完成任务；能力证据记录正确率、是否用提示、输出质量、评估来源。不把播放结束当听懂，不把转写相似当发音准确，不把输入正确当会写，不把 AI 分数直接换算成认证 CEFR。

## 6. 练习类型与反馈契约

| 练习 | 主要输入 | 反馈/证据 |
| --- | --- | --- |
| 听写 | 音频 + 用户文本 | 词/符号差异、重听片段、提示使用 |
| 听力理解 | 音频 + 选择/短答 | 主旨、细节、可核对的时间片段 |
| 阅读理解 | 原文 + 选择/短答/划线 | 答案依据、推理解释、词义语境 |
| 朗读/跟读 | 原文 + 录音 | 识别反馈与声学反馈分开显示 |
| 复述/场景任务 | 目标 + 用户录音 | 内容覆盖、可理解性、可改进表达；音频不可用时不伪造发音结论 |
| 拼写/打字 | 目标文本 + 键盘输入 | 已有即时反馈和符号兼容，继续复用 |
| 自主写作 | 情境 + 草稿 | 任务完成、结构、语法、表达；建议不是唯一标准答案 |
| 改写/迁移 | 原表达 + 新语境 | 语义保留、搭配是否合适 |

AI 出题必须带来源 block 引用、参考答案/可接受变体和生成版本；找不到依据则不发布题目。用户可报告错题，停用错误题不删除用户历史。反馈先给一至三个重要问题，再展开细节，避免一次全篇标红。

## 7. 今日计划：只保留一个调度核心

保存 minutesPerDay、可学习日、主要目标、当前课程；sessionsPerDay 保留旧数据兼容，但不再作为唯一预算。

今日展示：预计总时间、到期回忆、当前课程片段、一个薄弱点。复习过多时分批，不以“全部清空”阻止新课。默认不自动开始新的付费 AI 任务。

每个任务具备来源、推荐原因、预估时间、状态（待开始/进行中/完成/跳过/延期）。支持“今天只有 5 分钟”、换任务、继续上次、暂停和改天。已完成任务不因重新生成而消失；跨日任务保留其完成事件，不重复计数。

计划重排使用可解释规则先落地：到期程度、当前课程连续性、用户目标、近期薄弱项、预算。再根据实际完成时长校准估时，不先堆一个不透明的 AI 排课器。

## 8. 材料导入与内容管理

统一导入入口自动识别来源，保留现有解析器。流程：选择文件/链接 → 读取 → 提取/转写 → 质量检查 → 确认分课 → 加入课程。

处理任务持久化：queued / processing / needsReview / ready / failed / cancelled。浏览器离开后可恢复状态；需要长期执行的任务由服务端 worker 或桌面任务层负责，不能依赖某个 React 页面存活。

补齐：字幕 SRT/VTT 配对与偏移校正、章节/段落预览、转写文本编辑、标题和难度确认、重复检测、失败后只重试当前步骤。大文件在处理前展示大小、限制和可能成本。

数据保留三层：原始文件、提取文字/时间轴、学习用分块。校对不覆盖原始版本。PDF/EPUB 优先保留章节与页码锚点；扫描/OCR 结果标记待校对。网络来源失效时仍可读已合法导入的本地内容；不承诺绕过 DRM 或平台访问限制。

## 9. 学习页与翻译设计

桌面结构：顶部简短课时目标和进度；左侧可折叠目录；中央唯一练习工作区；下方一个主要动作。辅助解释按需抽屉展开，不复制一个整篇原文卡片。

移动结构：目录放入抽屉；当前句/段、译文、作答区相邻；底部动作跟随安全区和软键盘。不得让输入框被键盘覆盖，也不能依赖 hover、物理键盘快捷键完成核心流程。

翻译三种状态：隐藏、当前句、全部。学习偏好可记忆；测验模式单独控制。查看译文可继续学习，但本次结果明确“使用提示”，不装作无辅助测验。加载、错误、重试原位展示，不让卡片突然增高顶走输入区。

Type 默认只展示当前段落的字符反馈和内联译文；全文参考按需展开。保留长文阅读能力，同时在聚焦练习模式把上下文限制为当前段和少量相邻内容。字体、缩放、明暗模式和键盘焦点需要共同验收。

其他页面：材料列表优先展示处理/同步状态和继续入口；课程页展示学习目标而不只“4/4”；笔记页展示原文来源、个人例句和复习状态；复习页只需一个“开始复习”，分类留给筛选。

视觉沿用现有 Poppins/Open Sans、Indigo 与浅色背景。减少大面积淡紫正文、无信息的大卡片和多重阴影。正文优先深色，成功绿用于结果而不是整页文本。字体放大、375px 窄屏、键盘操作和屏幕阅读器纳入验收。

## 10. 收藏、复习与发音

收藏保留单词/表达、释义、原句、来源位置、个人例句；一个收藏可以关联多次出现的语境。不能仅凭相同文本合并不同词义和不同能力的复习状态。

统一调度但不粗暴合并 FSRS 卡：看到懂、听到懂、能拼出、能表达是不同证据。新模型保留 legacy 卡与 due，使用适配器接入，不批量重置熟练度。

复习从“翻卡看答案”扩展到回忆、听辨、填空、造句和换语境表达。失败生成明确的下一步，而不是永久停留在薄弱项列表。

发音沿用 48 项教学分类（现有代码已说明其中包含四个辅音组合），优先补最小对立听辨复测、词重音、句重音、节奏与连读。记录口音参考和服务商；原始录音可导出/删除；识别服务不可用时保留录音对比，不输出伪专业分数。

## 11. 数据模型演进与迁移

不要替换现有 ContentItem。现有 learningUnits / lessons 是可重建索引；用户编排应放在独立版本化结构，避免 reconcile 覆盖人工修改。

建议增量实体：

- `MaterialAsset`：owner、来源、hash、mime、大小、对象位置、本地可用性、上传状态。
- `SourceBlock`：materialId、version、原文区间、章节/页码、音频时间范围。
- `CoursePlan`：unitId、version、目标、课时排序与分块覆盖；区分派生默认值和用户覆盖。
- `ExerciseDefinition`：lessonId、skill、type、sourceRefs、prompt、答案/评分规则、版本、需要的能力。
- `Attempt`：exerciseVersion、sessionId、答案/录音引用、提示、反馈来源、各维度结果、开始/提交时间；不可用新评分覆盖旧证据。
- `DailyPlanTask`：dateKey、来源引用、预算、状态、完成事件引用。
- `ImportJob` 与 `SyncMutation`：持久化重试、幂等、错误和版本。

迁移顺序：备份与校验 → 新增表/字段 → legacy 适配读取 → 幂等回填来源映射 → 小范围功能开关 → 校验 → 切换。原资料、老 session、record、收藏卡全部保留；新增来源映射不能仅用内容 hash 作为永久身份，修改文字不能让整课历史失联。

Lesson 重分段时展示“新结构/历史记录”，通过 sourceRefs 映射覆盖证据；无法精确映射的记录保留历史归属，不强行视为新题通过。课程索引可重建，但用户定义的课程顺序不能随重建丢失。

## 12. Web / Desktop / iOS 能力契约

共用业务协议、练习定义、反馈展示与同步语义；为文件、音频、后台任务、离线存储设计平台适配层。不要为三端各维护一套课程逻辑。

| 场景 | Web | Desktop | iOS |
| --- | --- | --- | --- |
| 已缓存文本练习 | 离线可用目标，受浏览器存储限制 | 持久本地保存 | 本地保存，明确系统清理边界 |
| 大文件处理 | 上传任务/可恢复队列 | 本地后台处理优先 | 前台导入 + 服务端任务，不能假定退后台持续运行 |
| 录音/识别 | 权限与支持检测 | 原生/服务端适配 | 原生语音桥接及中断处理 |
| 在线 AI | 网络/额度检查 | 同左 | 同左 |
| 下载课程 | manifest + 完整性状态 | 本地目录/DB 配套 | 下载、空间管理与失效提示 |

上述是目标契约，不代表三端现在都具备。尤其 iOS 当前默认加载线上地址，启动 CI 通过不等于离线首次启动可用。

跨端验收至少覆盖：同账号接续一课、媒体缺失提示、飞行模式、键盘符号/IME、拒绝麦克风、来电/后台中断、登录退出、恢复备份。Windows/macOS/Linux 的包启动测试继续保留，不能用 Chromium 模拟替代全部原生交互验证。

## 13. SaaS 运营与 AI 质量

先补统一请求 trace、错误分类、导入成功率、同步积压和 AI 消耗观测。日志默认不保存全文资料、录音、密钥。用户应知道哪些内容将发送给哪个服务商，并可管理保留与删除。

已有请求限流保留；新增账户级用量记录、月度/任务预算、失败重试不重复扣减、并发上限。区分免费基础能力、用户自带密钥、平台托管 AI；付费订阅后置到核心闭环验证之后，不把基础拼写和查看本地资料做成依赖在线支付的能力。

账号删除、导出、云文件访问、RLS、密钥保存、采购/支付与应用商店规则需单独发布前审核。本次未检查线上配置，也不作合规认证。

AI 评估集覆盖文章/短语/带时间轴媒体、不同难度、合理同义答案、服务超时、无依据题目。写作反馈评估事实保真、语义不变、建议可操作性；口语的识别与声学评估必须分轨。导入资料中的文字属于待学习数据，不能当系统指令执行。

## 14. 分阶段交付与验收

| 阶段 | 内容 | 完成门槛 |
| --- | --- | --- |
| P0-A 数据可靠性 | 游标/分页/updatedAt/删除同步、同步清单、媒体备份 | 双设备和失败恢复测试通过；已知本机数据有明确可导出保障 |
| P0-B 真正的学习闭环 | 同一份材料的阅读理解 + 自主写作 + 反馈后再提交；复用原有听说打字 | 用户不离开课程可完成理解→输出→修订，历史稿保留；AI 失败可恢复 |
| P1-A 每日计划 | 统一时间预算队列与复习适配器 | 跨日/跨端继续、跳过/延期不假完成；计划重排不丢记录 |
| P1-B 导入可靠性 | 持久任务、字幕/章节校对、来源锚点 | 中断后可重试，能从题目回到原文位置，不重复创建资料 |
| P1-C 迁移训练 | 复述、个人例句、句子发音专项 | 错误→针对训练→新语境复测有可追溯证据 |
| P2 平台成熟度 | 下载离线、账户用量、托管额度、质量后台 | 成本和故障可观测；各平台能力有自动化与原生验收 |

顺序依赖：先修现有同步风险，不等所有新模型设计完成；新增 Attempt/课程编排协议供 P0-B 与后续计划复用；不要先大改所有页面再补数据。

每阶段独立 PR、迁移说明和回滚路径。数据迁移通过功能开关回退读取旧结构，不删除新产生的用户记录。时间估算在拆分开发任务和测试环境确认后再给，不以没有依据的工期承诺替代验收。

## 15. 成功标准与暂缓事项

核心指标：每周完成“理解 + 自主输出”的有效课时；辅助观察首次导入到第一次有效练习的转化、无提示复测表现、修改稿改善、跨端接续成功率、导入/同步失败率、每有效课时 AI 成本。先建立基线再设目标，不能用 star 数或打字量推断学习效果。

暂缓：社区排行榜、社交动态、教师后台、课程商城、再接大量同类模型、再加独立词汇/短语一级页面。待已有用户行为证明需求再投入。

# 导入可靠性修复与验证

## 范围

本轮修复远程获取的临时失败恢复、OpenRouter 专用 STT 接入、校对草稿强制刷新恢复，并继续跨端验证。未提交、未发布；不声称所有外网来源或物理设备均可用。

## 实现

- OpenRouter 服务端及大文件浏览器直传接入专用 `/api/v1/audio/transcriptions`，使用经当天官方模型列表确认存在的 `openai/whisper-large-v3`，不使用聊天模型代替识别。
- 能力解析、候选服务商、文件预检均支持 OpenRouter。专用识别模型不受聊天模型选择影响。
- 支持已知媒体扩展名携带操作系统通用 MIME `application/octet-stream`；不把系统未识别 MIME 误判为不支持。
- 转写请求增加时限；空转写结果明确失败，不创建空学习资料。HTTP 402 给出余额提示，不误报密钥错误。原资料保留。
- 远程 URL 对 502/503/504 增加一次重试；403/401/429 不换路径绕过限制。
- 校对变更同步写入当前标签页、当前数据库独立的 sessionStorage 恢复记录，只包含可编辑字段，不包含密钥或原文件。IndexedDB 继续为持久存储。旧版本、其他账号及已发布记录不会被恢复覆盖。
- 独立复核发现并修复异步提交与新输入之间的版本竞争，以及 AI/字幕更新后恢复旧字段的问题。恢复存储失败不能阻断已完成的数据库提交。
- sessionStorage 配额耗尽时提示用户等待数据库保存。该方案不承诺断电、清除浏览器数据、关闭标签页后仍能保留尚未持久化的数据。

- 生产构建及 TypeScript 通过。
- Chromium / WebKit：资料链路与可靠性回归 22/22 通过，包含标题、标签、正文修改后立即刷新恢复；五种非词书材料的五阶段学习；空文件、超限、不支持类型和重复文件。
- 首次标题强制刷新测试在两浏览器各重复三次，6/6 通过。并发保存与程序化更新另有 4 项恢复逻辑单测。
- Mozilla 公开 PDF 的实际 URL 抓取、校对、标签、发布、安排计划、进入课程，在两浏览器 2/2 通过。原 W3C 样本仍返回访问拒绝，未删掉原失败样本测试。

## 音频真实验证的外部阻塞

用 macOS 语音合成生成同一句公开测试语音，转换 WAV、MP3、M4A、OGG、FLAC、WEBM、MP4、AVI，调用真实导入转写接口。

修复通用 MIME 拒绝后，8 个格式均成功到达 OpenRouter，但服务商统一返回 HTTP 402：音频请求至少需要 US$0.50 账户余额。因此 **8 格式成功转写均未验收通过**。该结果只证明路由和错误返回，不证明解码或转写成功。MP4/AVI 样本本轮为音频容器，不代替真实带视频轨道的兼容验收。

脚本：`scripts/verify-import-audio.mjs`，密钥只从测试进程环境读取，未写入项目文件或用户浏览器设置。请撤销聊天中出现过的密钥，换新密钥安全配置后继续测试。
